# 论证链实验室

一个不要求注册的中文论证工具。用户可以从版本化题库开始，也可以写下自己的观点，让自己配置的 AI 服务把它整理为结构化候选。两种来源最终进入同一套确认流程：逐项判断事实 `F`、桥接原则 `B`、待说明结论 `V` 与当前基本价值 `G`。

正式报告不输出政治身份、左右坐标或人格标签，也不把 AI 生成内容直接当作用户立场。结果页另有默认关闭的娱乐覆盖层：它只报告基准库中的最近邻原型、论证路径相似度与覆盖度，不把相似度解释为身份概率。

## 两种问题来源，一套流程

- **正式题库**：浏览器读取 `public/bank/manifest.json` 指向的版本化 JSON，机械列出当前可用的全部理由和回答选项。
- **AI 生成**：浏览器通过 `pi-ai` 的服务商与模型目录，直接调用用户选择的模型服务商。AI 只能提出候选；用户可以编辑，确认后才写入本轮会话扩展。
- **自适应选题**：20 项政策组成候选库；单次评测先完成 8 项核心场景，再由当前候选间的信息增益选择 2—4 项区分题，不要求机械答完整个题库。
- **政策拆分**：把固定情景、政策选择、保障条件和数值参数分开；固定情景不要求赞成或反对，再记录整包立场和政策选择之间的取舍。
- **自由选题**：用户仍可按任意顺序开始、暂停或继续题目；阶段结果只统计已经结束的题目，进行中的步骤按题保存。
- **随时切换**：题库内容不符合用户想法时，可以在当前步骤输入自己的判断，让 AI 补出一条可继续核对的结构化理由，而不是中断流程。

回答选项不是固定三选一。每一步显示该题实际拥有的全部选项，自由输入由用户按需展开。

## 数据边界

| 数据 | 保存位置 | 是否自动上传 |
| --- | --- | --- |
| 结构化论证进度与已确认会话扩展 | 当前浏览器 `localStorage` | 否 |
| 未确认的自由输入草稿 | 当前标签页 `sessionStorage` | 否 |
| AI 配置、密钥与完整 AI 消息 | 当前页面内存；配置文本由用户自行保管 | 否 |
| 正式题库 | 同源静态 JSON | 只读下载 |
| 用户明确贡献的严格完整论证 | 私有 R2 候选区 | 仅在完整预览后单独确认并点击贡献时 |

调用 AI 时，用户刚输入的文字和当前必要论证上下文会从浏览器直接发送到其模型服务商，不经过本站服务器。用户确认结构化候选后，原始输入和 AI 对话不进入本地进度。公开贡献包也不包含原始输入、AI 对话、API 配置、时间、设备、账号或会话标识。

## 完整论证

现实政策推理默认表示为可撤销支持：

```text
F₁ ∧ F₂ ∧ … ∧ B  ⇝  V
```

- `F`：原则上可以判断真假的描述命题，包含支持条件与否定条件。
- `B`：说明这些事实为何能为结论增加一项理由的规范原则。
- `V`：当前正在说明的政策或中间规范结论。
- `G`：用户独立确认并通过结构相似案例检验后，本轮暂时停止追问的位置。

只有在现实判断模式中事实全部被判断为真、每层桥接原则均被接受、固定点被独立确认、压力测试没有限定或未说明张力、最强反方理由已经复核，且不存在当前链条冲突、情景不相容或题库缺口时，该论证才有资格进入公开候选区。条件性题设模式只检验“如果这些经验描述成立”的规范结构，不把题设数字当作已经核实的现实事实。

结果页首先展示压缩后的“政策拆分 → 首要理由 → 暂定出发点 → 反例边界”，点击后才展开完整论证。价值两难只形成局部关系，不生成统一价值排名；可选的最近邻匹配只使用当前有效的已闭合路径和带依据的基准项。未回答、撤回、张力与题库缺口不增加覆盖度，也不按不一致处罚。

## 题库与贡献流水线

1. 静态站点读取正式基础题库和已审核社区扩展。
2. 用户确认的 AI 候选只进入本地会话扩展，不会修改正式题库。
3. 用户在结果页检查完整预览，并独立勾选公开贡献确认。
4. Cloudflare Worker 只接受严格白名单贡献包，规范化、扫描敏感格式并按内容哈希写入私有 R2。
5. GitHub Actions 定期读取小批候选，重新校验、去重并建立公开审核 PR。
6. 只有人工合并后，内容才进入 `public/bank/community-contributions-v1.json`，随下一次静态发布成为正式题库扩展。

## 本地开发

项目固定了依赖版本，可继续使用 Volta 管理 Node.js：

```powershell
npm install
npm test
npm run build
npx playwright install chromium
npm run test:e2e
npm run dev
```

也可以使用 Deno 2 的 npm 兼容层。仓库中的 `deno.json` 已启用 `nodeModulesDir: auto`：

```powershell
deno task test
deno task build
deno task dev
```

前端生产构建不需要执行依赖生命周期脚本。Worker 本地开发与部署仍建议使用 Volta/npm 提供的 Wrangler：

```powershell
npm run dev:worker
```

候选区地址可以在构建时通过 `VITE_BANK_ENDPOINT` 设置，也可以在静态构建后修改 `dist/runtime-config.js`：

```js
window.__ARGUMENT_CHAIN_BANK_ENDPOINT__ = 'https://bank.example.com';
```

地址为空时，结果页仍可下载完整贡献包，但不会发出上传请求。

## 主要目录

- `public/bank/`：题库清单、基础题库和人工审核后的社区扩展。
- `src/data/model.js`：只读正式题库与本地会话扩展的运行时适配层。
- `src/lib/engine.js`：确定性论证状态机、政策拆分取舍、冲突与情景兼容性处理、敏感性和逐项反方复核。
- `src/lib/ideology.js`：自适应选题、基准原型最近邻匹配和稳定分享短码。
- `src/lib/aiAgent.js`：浏览器内 `pi-ai`／`pi-agent-core` 集成。
- `shared/`：浏览器、Worker 和审核脚本共享的贡献契约。
- `worker/`：只接收明确贡献的 Cloudflare Worker 与 R2 写入边界。
- `tests/`：正式浏览器回归测试，覆盖组件取舍、自适应流程、完整论证、击败者复核、刷新迁移、价值两难和移动端布局。
- `docs/adr/`：隐私、题库、AI 与贡献边界的架构决定。

更完整的模型、协议和部署说明见 `docs/MODEL.md`、`docs/PROTOCOL.md` 与 `docs/DEPLOY.md`。
