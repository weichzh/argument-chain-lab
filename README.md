# 论证链实验室 0.5

一个从具体政策判断出发，逐步追问“你相信哪些事实”“你接受哪条规范原则”“为什么接受这条原则”的中文研究原型。它不输出政治身份、左右坐标或“最接近意识形态”，而是保存用户亲自确认、拒绝、暂不判断、补充条件和修改过的理由链。

## 核心形式

命题 1.1 给出的是模型论上的必要约束：若评价谓词不能由描述语汇定义，纯描述前提集不能独自固定评价结论。

```text
F₁ ∧ F₂ ∧ … ⊭ V
```

因此，任何从事实判断走向政策判断的路径都必须显式出现至少一条含规范内容的桥接原则 B。现实政策理由通常还存在反例、例外、竞争理由与不确定性，所以系统把实际推理表示为可撤销支持：

```text
F₁ ∧ F₂ ∧ … ∧ B  ⇝  V
```

只有当 B 被形式化为充分条件、且所有相关前提都被纳入时，才能把该步升级为严格蕴含 `⊨`。

- `F`：非评价性描述命题，具有判真条件与反驳条件；“暂不判断”是认识状态，不是第三种真值。
- `B`：包含规范内容的桥接原则。它在下一层可以成为新的待说明结论 `V′`。
- `V`：当前政策结论或中间规范结论。
- `G`：用户经过单独确认后接受的本轮当前基本价值；它只是这次对话中暂时停止继续追问的位置，不是系统宣布的客观公理。

## 面向用户的语言规则

0.5.0 版本把形式模型和用户看到的中文分开维护。技术符号保留，但不要求用户先懂术语：

- 每个新概念第一次出现时，先用完整中文说明它在本题中表示什么，再给一个直接例子；
- 每个事实命题都同时显示“这句话具体在问什么”“什么会支持它”“什么会否定它”；
- 每条规范原则都说明它新增了哪项价值判断，并强调它只增加一项理由，不自动证明政策结论；
- “当前基本价值”必须与“我只是暂时想不到更深理由”明确区分；
- 结果页使用“理由是否说明完整”“事实是否确认”“适用条件是否清楚”等普通中文，技术状态只保留在数据结构中；
- 正式的模型论证明放在可展开附录中，不会挡在答题流程前面。

所有显示层改写集中在 `src/data/readableText.js`。它只改写说明方式，不改变 F、B、V、论证连接和评分状态机。

## 对话协议

每项政策都按同一机械状态机运行：

1. 用户先选择政策结论或保持悬置。
2. 系统列出多条可能的实际理由，而不是直接把答案换算成价值轴。
3. 每条理由拆成一个或多个 `F`、一条 `B` 与当前 `V`。
4. 用户分别判断事实真值状态与是否接受 B。
5. 接受 B 后，系统把 B 变成下一层 `V′`，继续问“为什么”。
6. 用户可以提名一个候选固定点，但必须在下一屏明确区分：
   - 即使没有更深规范前提，我仍独立接受它；
   - 我只是暂时想不到更深理由；
   - 我拒绝把它当作独立起点；
   - 继续追问题库中的更深路径。
7. 已确认固定点还要经过结构相似反例，检验其适用范围。
8. 多项政策完成后，只有同时涉及两个已确认固定点的预设两难题才会出现，用于形成局部价值优先关系。

## 冲突与失败状态

- 同一 F 被回答为真与假，或同一 B 被接受与拒绝时，推导立即暂停。
- 用户必须选择修订旧判断、撤回当前判断、标记命题范围不足，或整体悬置。
- “这些都不是我的理由”会形成题库缺口，不会被强制匹配到最接近选项。
- 事实前提为假或未知时，规范链仍可继续检验，但最终只记为条件性闭合，不算现实政策结论的完整支持。
- 反例无法处理、固定点未确认或桥梁被拒绝时，系统保存停止位置，而不是补造一个价值前提。
- 两难结果允许平局、拒答与偏好循环；系统不强制生成完整、传递的价值总序。

## 当前题库

当前版本刻意保持少量政策入口，把主要复杂度放在中间论证层：

- 4 个政策入口
- 57 个描述命题 F
- 52 条有类型的论证模板
- 42 个规范命题或政策结论
- 13 个可作为反思终点的基础价值候选
- 9 个仅在两个端点都已确认后才出现的跨价值两难
- 最长预设递归路径为 4 层桥接

题库快照位于 `public/model-0.5.0.json`。


## 中文可读性规则

0.5.0 版把严格命题与面向用户的解释分成两层，避免为了通俗而改变命题内容：

- 每条事实命题先显示经过中文改写的命题正文，再显示“这句话具体在问什么”；
- “怎样判断这句话”区域分别说明支持条件与否定条件，原有严格判准仍保留在可展开区域；
- 每条规范原则同时提供普通中文解释和一个具体适用例；
- 每张理由卡只概述推理步骤，不再重复整段长事实命题；
- F、B、V、G、`⇝` 与 `⊨` 第一次出现时都有定义和例子；
- 模型校验会检查上述解释字段是否齐全，并对过长命题和理由摘要提出警告。

用户界面中的例子用于说明概念或适用结构，不替代事实证据，也不改变原命题的真假条件。

## 开发与验证

```bash
npm install
npm test
npm run export:model
npm run build
npm run bundle:single
npm run dev
```

主要文件：

- `src/data/model.js`：F、B、V、递归论证、政策入口、反例与两难。
- `src/data/readableText.js`：面向用户的通俗中文、逐项解释、具体例子和事实判定说明。
- `src/data/readableText.js`：面向用户的中文改写、逐题解释、例子与简明论证步骤。
- `src/lib/engine.js`：确定性状态机、承诺记录、冲突处理、链条分类和局部价值优先关系。
- `src/components/Assessment.jsx`：递归苏格拉底式问答。
- `src/components/ProofView.jsx`：实时 F／B／V 论证账本。
- `src/components/DilemmaFlow.jsx`：基于已确认固定点生成两难题。
- `src/components/ResultsV2.jsx`：论证链、固定点、事实信条、断点与局部优先报告。
- `docs/MODEL.md`：题库类型约束、停止规则与审核标准。
- `docs/PROTOCOL.md`：从政策结论到固定点、冲突处理与两难比较的机械状态机。
- `docs/RESEARCH.md`：分析哲学、元伦理学与形式论证来源及保留意见。

## 数据与安全

回答只存于浏览器 `localStorage`，可导出 JSON。结果属于敏感政治与价值信息，不应用于政治审查、就业、执法、信贷、教育录取或其他高风险决策。
