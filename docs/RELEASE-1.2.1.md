# 1.2.1：理由连续性与读者体验维护

## 兼容边界

应用版本为 1.2.1，正式题库与 benchmark 仍为 1.2.0。13 项政策、302 条策展理由及其 ID 没有变化。继续使用 v10 进度格式；旧版 1.0/1.1 进度仍兼容，0.9 仍只读归档。

## 修复

深层自定义理由通过已确认路径末端确定说明对象，而不是沿用政策根判断。手写草稿、AI 请求、确认检查、持久记录和结果详情使用一致的目标。旧的进行中记录可以恢复正确目标；已经结束但未记录自定义目标的旧记录只保留原文，不补造其历史含义。

结果详情同时显示此前的策展步骤与自定义补充。补充内容保持 `custom_unverified`，不因保存就变成已核实假设、已检查案例或已确认停止点。形式检查继续核验自定义补充之前的结构化步骤；matcher 3.2 只把 accepted/qualified 路径的末端计为已检查停止点。

对修改方案回答“不确定”会明确记录尚未判断的框架，不再被摘要写成拒绝全部修改。继续追问但暂时保留为未解决时，前面的步骤不会丢失。浏览器保存失败会显示警告，当前内存中的答题与导出仍可使用。

## 文案与阅读

首页说明 8 个政策情景可以分次完成、任选起点且不依赖 AI；不承诺发现唯一动机。修改被拒绝只表示该修改不足以改变判断，不推断用户一定还有另一种动机。采用假设不表示系统已经核实事实，暂停追问也不表示找到不可质疑的最终答案。

娱乐结果比较的是当前路径，不把相似度说成身份概率；覆盖指标和百分点差距单独解释。AI 候选页区分保存、接受与检验。详细理由正文增大字号，长文本可以换行。

## 验收

`npm run test:release` 依次运行单元/契约/模型/匹配检查、生产构建和 Chromium 回归。当前浏览器套件有 21 项，包含完整深层补充与导出、刷新恢复、未解决摘要、模拟存储不足、AI Responses SSE 成功候选与失败保护，以及 320/390/768/1440 像素宽度和放大文本检查。

AI 成功用例使用受控模拟服务验证实际 SDK、候选确认和持久化边界，不消耗真实服务商凭据，不等于验证所有服务商的网络、跨域配置和输出质量。

构建生成 `release.json`，用于核对部署产物对应的完整源码提交和题库哈希。发布结论分别记录本地验收、Sites 终态和线上关键路径，不把保存版本或开始部署当作发布成功。

旧 R2 贡献归档工作流改为手动触发；新版前端没有接入旧贡献协议，不应为一条未使用通路制造每日失败告警。

## 尚需独立工作的范围

本轮没有把 23 个候选参考名称升级为已充分整理的历史原型，也没有宣称 75 项参考库完成独立的方法验证。后续内容工作应逐条审查题设是否清楚、理由是否代表被描述的立场、相似案例是否真正对齐，而不是只增加标签数量。

新版公开贡献流程仍需要单独设计与审核；不能直接接回旧版贡献包。测试覆盖不意味着所有自然语言歧义或所有浏览器行为已经被穷尽。
