# 1.3.0 使用完整性修复验收

本轮确认的代码与题库问题已修复，并通过本地发布前验收；正式上线与外站真实结果的可视化对照仍未完成。基线：1.2.2 / d11c1d64390af7cd4ab2f7f679ee0f608cde71cf。关联 Issue：#1。

## 已实施

- 逐题检查点、跨题保存、只回退本题、完成检查点刷新；列表默认继续或查看小结，重答需确认且可取消。
- 用户实际判断与正在检查的反方命题分别呈现；接受、拒绝、不确定及未测试的修改不再混用。
- 用户记录完整度不随参考集合变化；可选补答计入用户记录但不抬高核心题覆盖。双方可比覆盖和参考质量分开说明。测试、待整理条目不进入默认比较，双方不确定不算肯定相似。
- 公共参与、劳动者治理僵局以及两条元数据组合理由采用独立修订 ID。旧定义保留。修正残句、错接原则与充分/必要偷换，专家建议暂停明确决定主体。
- 不确定原因可选保存，并可继续比较其他修改。理由可以先记录为未检验，再从原位继续；拒绝前提或适用性保留为未确认尝试。
- 完成一题立即显示小结，结果先展示实际判断边界；参考卡片后置、按名称排列，提供可读 Markdown 与独立 JSON 导出。
- 移动端减少重复说明并增加阶段提示；完整方案和关键固定条件保持展开，字号、焦点与无横向溢出保持验收。
- v4 旧会话保留来源及可确定发生过的顺序比较；旧专家权限不自动解释成新方案，0.9 仍为只读归档。

构建提示保留在日志：第三方 AI 包 `node:fs` 外部化、测试环境颜色变量提示。模拟 AI 成功、失败、隐私边界和存储不足路径通过；没有声称实测所有付费服务商。

证据保存在 `.tmp/acceptance-1.3.0/`：`release-tests.log`、`reference-simulation.log` 与 `browser/` 截图。测试使用可重建的合成分支样本 `tests/fixtures/ux-session.js`，不是个人政治记录，也未上传到外站。

## 参考站人工接力

早期可见浏览器启动尝试失败后，已通过 Linux 用户服务启动独立 Chrome：`acl-reference-human-browser.service`，隔离资料目录 `.tmp/reference-human-standalone`，仅本机调试端口 47833。已进入参考站第 1/73 题，等待用户填写真实答案；没有修改日常浏览器配置或登录状态，也没有提交模拟政治答案。

完成后保留结果页，再在仓库执行：

```bash
node scripts/capture-reference-result.mjs
```

脚本只连接本机的目标标签页，不替用户点击答案。非完成页、预览跳过模式和错误结果不能作为正式结果保存。完成后将渲染 HTML、自包含 MHTML 与完整截图写入私有 `.tmp/reference-human-result/`；个人结果不得提交公开仓库。

截至本轮收尾，参考站仍停在第一题，因此正式结果页尚未保存，不能声称已研究该份正式结果的可视化。
