# 递归论证审查协议

本协议把一次评测定义为用户逐题决定是否回答的一组政策问题。产品前台只有一条一屏一问的流程；形式结构用于减少问题，不用于要求用户学习论证术语。

## 1. 单项政策流程

对每个进入答题流程的政策入口 `P`：

1. **先问上位判断**：用户支持、反对、只在某些条件下支持，或暂时不能判断。题干已经排除的范围属于问题边界，不再要求用户逐项确认。
2. **按回答生成下位问题**：支持或反对直接进入理由；暂时不能判断结束当前政策；只有条件性支持才询问会改变可接受范围的手段、保障或参数。被上位判断排除的下位问题不得生成。
3. **选择实际理由**：系统显示与当前方向相关的预审理由。只显示用户可直接理解的标题；预设理由不合适时，用户可以记录缺口或让 AI 提出结构化候选。
4. **采用或拒绝题设假设**：需要经验前提时，系统询问用户是否愿意暂时采用该描述作为本题假设。用户可以采用、拒绝或悬置；产品不再提供平行的现实判断模式。
5. **核对判断依据**：系统用普通话询问，即使题设假设成立，该判断是否足以成为支持当前结论的理由。接受只增加一项可撤销支持，不表示结论已经被证明。
6. **只问可能改变结果的问题**：形式检查器在后台判断前提、范围、例外和竞争理由。只有一个缺口仍可能改变当前结果时，才显示对应的普通问题；不相关检查直接跳过。
7. **继续追问为什么**：接受当前理由后，用户可以继续追问，选择“这就是我目前最根本的理由”，或表示暂时说不清。继续追问时，当前判断依据成为下一层待说明内容。
8. **换对象检查**：用户选择停止后，系统优先使用题库已有的相似案例；没有专门测试时，可以使用题库中的普通案例生成一次换对象检查。用户不需要先理解或制作论证结构。
9. **考虑相反理由**：系统展示当前方向最值得认真对待的相反理由。只有其前提和判断依据得到采用时，才询问它是不会改变、造成犹豫、暂时抵消，还是改变最终判断。
10. **进入下一题**：当前政策结束后，系统自动进入列表中的下一道未完成题目；用户也可以直接跳过当前题，且跳过不会生成一条未解决结论。到达列表末尾后进入结果页。

内部仍可保存 `F + B ⇝ V`、递归层次、攻击关系和形式证书，但这些标识不得出现在默认答题流程中。

## 2. 题目选择

题目列表保留为产品入口，但不提供开始前多选。用户可以直接从第一题开始，也可以从任意一道题开始；系统随后按列表顺序继续，每道题都允许跳过。不要求完成整个题库，也不在开始前要求选择方法或模式。

完成、进行中、已跳过和未开始状态按政策保存。用户可以随时回到列表，继续或重新回答某一道题。自动推荐和固定核心题量不再构成用户流程。

## 3. 回看、修改与冲突

当前答题过程中始终提供“回到主页”“上一题”“查看已答”“题目列表”和“中止并看结果”。“查看已答”使用普通句子概括已经确认的判断；用户点选一条回答后回到该回答之前，之后依赖它的回答被丢弃并按新路径重新询问。

主页允许继续当前进度，也允许在二次确认后清除答题进度和临时草稿，从第一题重新开始。

进行中的结构化草稿按政策保存在当前浏览器，刷新或返回列表后可以继续。未确认的自由输入仍只保存在当前标签页。

同一命题出现决定性相反回答时，状态机立即暂停，并询问用户要保留哪一个回答、暂时悬置，还是说明两个情境范围不同。系统不得静默覆盖，也不得把矛盾解释为人格缺陷。

## 4. 后台形式检查

形式检查器负责三件事：

1. 判断当前回答是否足以支持下一步；
2. 判断候选问题是否仍可能改变结果；
3. 判断是否出现前后冲突、情景不相容或结论范围扩大。

检查器可以保存类型、前提、规则、攻击边、grounded 标记和证书哈希。前台只显示由检查结果触发的普通问题，不显示 `F`、`B`、`G`、固定点、击败者、辩证状态、条件性闭合、张力或形式证书等内部术语。

## 5. 结果

默认结果只包含：

- 用户对每项已完成政策的最终判断；
- 用户选择的主要原因；
- 相反理由是否造成犹豫、抵消或改判；
- 题设假设没有因此被认定为现实事实的说明。

默认结果不显示闭合、张力、未完成数量或形式状态统计。用户可以选择“修改回答”或“查看详细推理过程”；完整命题、形式检查、来源、导出和贡献信息只在详细视图中出现。最近邻原型继续作为默认关闭的可选娱乐层，不表示政治身份或概率。

## 6. AI 候选

AI 不是第二套评测模式，只是当前问题缺少合适选项时的候选来源：

1. 未确认自由输入只保留在当前标签页草稿中。
2. 浏览器把输入、当前待说明判断和必要题库切片直接发送给用户配置的模型服务商。
3. `pi-agent-core` 只允许模型调用一次结构化候选工具，且 `schemeId` 必须来自当前方案目录。
4. AI 不允许直接修改已确认状态或签发形式证书。
5. 用户确认后，候选转换为带 `local_` ID 的会话扩展，并进入同一状态机。

正式题库 ID 不允许被会话扩展覆盖。刷新恢复时，运行时只接受 `local_` 命名空间中的结构化扩展。

## 7. 公开贡献

本地保存、调用 AI 和公开贡献是三个互不替代的动作。主问卷采用题设假设，因此不会把条件性回答伪装成现实证据；只有另行补足现实证据，并通过前提、范围、相似案例、相反理由、冲突、情景兼容性和形式检查后，结果才可能生成严格贡献包。

用户必须先展开详细推理并检查完整预览，再单独勾选贡献确认并点击提交。Worker 只接受白名单贡献包；未知字段使请求整体失败。进入私有候选区不等于进入正式题库，后续仍必须经过公开 PR 与人工合并。
