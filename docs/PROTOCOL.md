# 递归论证审查协议

本协议把一次评测定义为若干条可中断、可修订的规范论证链，而不是把政策答案直接换算为政治坐标。

## 1. 单项政策链

对每个政策入口 `P`：

1. **检查政策拆分**：固定情景只供核对，不要求支持或反对；政策选择、保障条件和数值参数分别使用适合其语义的回答。独立回答不自动决定整包立场。
2. **确定当前结论 `V₀`**：用户支持、反对、悬置，或任选一个方向作思想实验。整包立场与具体政策元素分开保存；一条理由默认只支持或反对它实际覆盖的元素。若政策选择与整包立场存在分歧，再记录整包底线与愿意交换的选择。
3. **选择实际理由**：系统显示当前结论实际拥有的全部预审模板 `Rᵢ = ⟨Fᵢ, Bᵢ, V₀⟩`，不把界面固定为三选一；用户也可直接输入自己的理由。
4. **逐项检验 `Fᵢ`**：开始答题前选择事实回答方式。条件性题设模式只记录是否采用该经验描述作为本轮假设；现实判断模式记录相信真、相信假或暂不判断。后者是认识状态，不改变命题的二值真值语义。两种回答不能在同一轮中途互换。带阈值情景的事实还记录在哪个幅度下理由开始翻转。
5. **检验 `Bᵢ`**：用户接受、拒绝或悬置桥接原则。接受只表示 `Fᵢ + Bᵢ ⇝ V₀` 获得一项可撤销支持，不表示该结论已被演绎证明或压倒全部反对理由。
6. **递归**：若接受 `Bᵢ`，令 `V₁ := Bᵢ`，重新执行步骤 3—6：

   ```text
   F₀ + B₀ ⇝ V₀
   F₁ + B₁ ⇝ B₀
   F₂ + B₂ ⇝ B₁
   …
   ```

7. **暂定出发点确认**：任何已经接受的规范桥梁 `Bₖ` 都可以成为停止点候选。用户提名后，系统必须再问一次：即使暂时拿掉其他规范前提，是否仍独立接受它。若题库没有结构化反例，用户或 AI 必须先补充一个可检查的相似案例；完成压力测试后才记录为本轮暂定出发点 `G`。
8. **反例压力**：用结构相似但政治对象不同的案例测试 `G`。用户可保持适用、提出相关区别、承认未说明例外、撤回或悬置；提出限定区别的链仍记为有张力，不能直接成为严格完整链。
9. **最强反方理由**：对已经闭合的方向展示相反方向的候选理由。反方事实和桥梁进入与主链相同的命题冲突索引。用户先逐项回答其事实前提和判断依据；若前提全部成立且桥梁被接受，这条反方论证已经建立，只能继续判断它是补充限制、削弱但不改立场、与原理由抵消还是压过原理由，不能再把它标成“不接受”。理由链闭合状态与复核前后的整包立场分别保存。
10. **形式检查与保存状态**：对已有 `ArgLogic` 映射的路径，系统分别保存规则结构、前提建立状态、结论覆盖范围和待核批判问题。链条另行分类为完整闭合、条件性闭合、适用范围张力或未闭合，并保存停止位置与修订历史；流程闭合不等于形式有效。

## 2. 自适应选题

单次评测不要求完成全部候选政策。当前版本先按优先级完成 8 项核心场景，再从 12 项自适应场景中选择 2—4 项。每完成一项，系统重新比较当前最接近的原型变体，并以候选立场分布的熵作为主要信息增益；尚未覆盖的规范领域获得小幅优先。

达到最少自适应题量后，若前两名路径相似度差距与覆盖度同时达到停止阈值，政策阶段结束；达到最多题量仍无法唯一化时也停止，不用任意规则强选标签。之后最多进入一道由已确认固定点触发的价值两难。

## 3. 实时冲突处理

同一命题出现决定性相反回答时，状态机立即停止。用户必须选择：

- 用当前回答修订此前回答；
- 撤回当前回答并保留此前回答；
- 记录题库把不同语境错误合并为同一命题；
- 把双方都改为未知／悬置。

系统不得静默覆盖，也不得把矛盾直接解释为人格缺陷。

事实还可声明互斥情景与前置依赖。跨链出现不相容情景、被否定的依赖或命题冲突时，相关链条重新分类为张力；先前固定点事件标记为已孤立或已取代，不继续作为当前有效承诺。

## 4. 跨政策价值比较

完成若干政策链后，系统汇总本轮真正得到确认的 `G`。两难题只有在两个端点都属于这些已确认固定点时才可出现。

每道两难固定尽可能多的经验条件，只要求用户记录局部关系，例如：

```text
G₁ ≻ G₂
G₁ ≈ G₂
G₁ ? G₂
```

结果允许不完备、不传递和循环；不得强制生成单一总分或完整价值全序。

## 5. 机械输出

最终报告只输出：

- 每条 `F + B ⇝ V` 的来源和回答；
- 已确认、拒绝、撤回或未确认的固定点；
- 事实信条及其真值条件；
- 冲突、题库缺口、反例例外与条件性闭合；
- 两难题产生的局部价值优先关系。

正式报告不输出政治身份诊断，也不把暂定固定点称作客观公理。其主视图是“政策与组件 → 理由族 → 暂定固定点 → 反例边界”的论证谱系，并提供同答异因比较和局部价值关系。

用户可另行开启娱乐覆盖层。该层把结果称为“基准库中的最近邻原型”，只报告路径相似度、与第二名差距、覆盖度和稳定性；相似度不是身份概率。当前有效权重为政策整包 10%、政策拆分 15%、理由族 30%、暂定出发点 25%、反例与范围 10%；基准库尚无两难回答，因此两难权重为 0。标签启发式只用于自适应选题，不进入最终得分。低覆盖不生成单一历史标签，中等覆盖保留前三名，只有覆盖和领先差距同时充分时才显示唯一最近邻。

## 6. AI 候选状态转换

AI 不是第二套评测模式，只是当前步骤的另一种问题来源：

1. 未确认自由输入只保留在当前标签页草稿中。
2. 浏览器把该输入、当前待说明结论、已确认论证图和必要题库切片直接发送给用户配置的模型服务商。
3. `pi-agent-core` 只允许模型调用一次结构化候选工具，不允许它直接修改已确认状态。
4. 用户可以逐字段检查和修改候选；关闭候选不会改变论证状态。
5. 用户确认后，候选被转换为带 `local_` ID 的会话扩展，并进入与正式题库完全相同的 F／B／V／G 状态机。
6. 原始输入和完整 AI 消息不进入本地进度；AI 配置只在当前页面内存中。

正式题库 ID 不允许被会话扩展覆盖。刷新恢复时，运行时只接受 `local_` 命名空间中的结构化扩展。

## 7. 公开贡献状态转换

本地保存、调用 AI 和公开贡献是三个互不替代的动作。只有一条链满足 `complete`，且相关事实、桥接原则、固定点、压力测试、最强反方理由、冲突、情景兼容性、题库缺口和已有形式检查全部通过严格检查时，结果页才生成贡献包。贡献包用 `formalizationCoverage` 区分 `complete`、`partial` 和 `none`；尚未形式化的候选可以进入人工审核，已有形式化但包含 error 的论证不能进入候选区。

用户必须先查看完整预览，再单独勾选贡献确认并点击提交。条件性题设模式没有确认经验前提在现实中成立，因此不能生成严格完整贡献。Worker 只接受白名单贡献包；任意未知字段都会使请求整体失败，不会被静默删除。进入私有候选区不等于进入正式题库，后续还必须经过公开 PR 与人工合并。
