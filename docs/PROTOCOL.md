# 递归论证审查协议

本协议把一次评测定义为若干条可中断、可修订的规范论证链，而不是把政策答案直接换算为政治坐标。

## 1. 单项政策链

对每个政策入口 `P`：

1. **确定当前结论 `V₀`**：用户支持、反对、悬置，或任选一个方向作思想实验。
2. **选择实际理由**：系统显示当前结论实际拥有的全部预审模板 `Rᵢ = ⟨Fᵢ, Bᵢ, V₀⟩`，不把界面固定为三选一；用户也可直接输入自己的理由。
3. **逐项检验 `Fᵢ`**：每个事实前提只能回答相信真、相信假或暂不判断。后者是认识状态，不改变命题的二值真值语义。
4. **检验 `Bᵢ`**：用户接受、拒绝或悬置桥接原则。接受只表示 `Fᵢ + Bᵢ ⇝ V₀` 获得一项可撤销支持，不表示该结论已被演绎证明或压倒全部反对理由。
5. **递归**：若接受 `Bᵢ`，令 `V₁ := Bᵢ`，重新执行步骤 2–5：

   ```text
   F₀ + B₀ ⇝ V₀
   F₁ + B₁ ⇝ B₀
   F₂ + B₂ ⇝ B₁
   …
   ```

6. **固定点确认**：用户提名某一 `Bₖ` 为停止点后，系统必须再问一次：即使暂时拿掉其他规范前提，是否仍独立接受它。只有明确接受时才记录为本轮暂定固定点 `G`。
7. **反例压力**：用结构相似但政治对象不同的案例测试 `G`。用户可保持适用、提出相关区别、承认未说明例外、撤回或悬置。
8. **保存状态**：链条被分类为完整闭合、条件性闭合、适用范围张力或未闭合，并保存停止位置与修订历史。

## 2. 实时冲突处理

同一命题出现决定性相反回答时，状态机立即停止。用户必须选择：

- 用当前回答修订此前回答；
- 撤回当前回答并保留此前回答；
- 记录题库把不同语境错误合并为同一命题；
- 把双方都改为未知／悬置。

系统不得静默覆盖，也不得把矛盾直接解释为人格缺陷。

## 3. 跨政策价值比较

完成若干政策链后，系统汇总本轮真正得到确认的 `G`。两难题只有在两个端点都属于这些已确认固定点时才可出现。

每道两难固定尽可能多的经验条件，只要求用户记录局部关系，例如：

```text
G₁ ≻ G₂
G₁ ≈ G₂
G₁ ? G₂
```

结果允许不完备、不传递和循环；不得强制生成单一总分或完整价值全序。

## 4. 机械输出

最终报告只输出：

- 每条 `F + B ⇝ V` 的来源和回答；
- 已确认、拒绝、撤回或未确认的固定点；
- 事实信条及其真值条件；
- 冲突、题库缺口、反例例外与条件性闭合；
- 两难题产生的局部价值优先关系。

报告不输出政治身份诊断，也不把暂定固定点称作客观公理。

## 5. AI 候选状态转换

AI 不是第二套评测模式，只是当前步骤的另一种问题来源：

1. 未确认自由输入只保留在当前标签页草稿中。
2. 浏览器把该输入、当前待说明结论、已确认论证图和必要题库切片直接发送给用户配置的模型服务商。
3. `pi-agent-core` 只允许模型调用一次结构化候选工具，不允许它直接修改已确认状态。
4. 用户可以逐字段检查和修改候选；关闭候选不会改变论证状态。
5. 用户确认后，候选被转换为带 `local_` ID 的会话扩展，并进入与正式题库完全相同的 F／B／V／G 状态机。
6. 原始输入和完整 AI 消息不进入本地进度；AI 配置只在当前页面内存中。

正式题库 ID 不允许被会话扩展覆盖。刷新恢复时，运行时只接受 `local_` 命名空间中的结构化扩展。

## 6. 公开贡献状态转换

本地保存、调用 AI 和公开贡献是三个互不替代的动作。只有一条链满足 `complete`，且相关事实、桥接原则、固定点、压力测试、冲突和题库缺口全部通过严格检查时，结果页才生成贡献包。

用户必须先查看完整预览，再单独勾选贡献确认并点击提交。Worker 只接受白名单贡献包；任意未知字段都会使请求整体失败，不会被静默删除。进入私有候选区不等于进入正式题库，后续还必须经过公开 PR 与人工合并。
