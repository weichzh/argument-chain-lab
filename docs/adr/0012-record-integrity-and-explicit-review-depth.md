# 将用户记录完整度与参考可比覆盖分开，并保留逐题检查点

## 决定

1.3.0 保持完整政策框架和顺序比较，不恢复“有条件支持”初始按钮。接受一个已测试修改，只证明该修改足以改变本轮判断，不证明它必要、最小或最佳。未测试和不确定的修改不属于已拒绝修改。

每道题保存独立检查点。默认打开操作用于续答或查看完成小结；重答使用独立动作并经用户确认。回退只恢复当前政策的状态和回答，不覆盖其他题后来完成的记录。已完成检查点必须刷新，不能被早先的未完成草稿覆盖。

用户可以先保存所选理由，暂不进行检验。这种记录必须标记 `unchecked`，保留 `selectedReasonId`，不伪造前提、原则确认、停止点或相似案例；从结果或题目列表可以继续原来的检查。不同意前提、不同意原则或认为原则不适用于当前担忧，分别保存为未确认的尝试，不说用户没有理由。

## 指标边界

- 记录完整度：仅根据用户已记录字段计算的工程指标，不能称为思想深度、理性程度、立场强度或身份概率。前台首先展示已作答、所选理由、已核对理由及案例的实际数量。
- 双方可比覆盖：用户与某个参考同时具备的明确字段，占用户可用于比较信息的比例。参考资料缺失不减少用户记录数量。
- 有证据支持的相同记录：按固定用户信息分母比较，避免稀疏参考仅凭较少重叠字段获得不当优势。资料缺失不记为反对，也不作为肯定相似证据；双方不确定不代表相同立场。

测试用假想参考和待独立整理的参考保留在完整维护文件中，只供显式内部模拟，不进入默认产品比较。前台的参考卡片按名称排列，展示具体相同点、差异、覆盖与来源限制，不把名称当成用户身份或立场优劣排名。

## 内容与版本

1.2.2 文件保持原字节。四条语义修订理由采用新 ID，旧定义只用于显示与验证旧记录。公共参与与争议解决分别有自己的原则和具体相似案例，不再借用出身资源差距或市场协调原则。

专家建议暂停的修改明确由议会决定是否暂停。旧版本的题设和框架标签保留为来源版本数据，旧回答不得自动解释为认可这项新权限安排；参考比较只使用其仍可比较的原方案判断。旧 v4 顺序进度只恢复流程必然记录的已测修改，不据此补充偏好或理由。

结果先呈现实际判断、可接受修改、未确定处和推理记录，再提供可选参考比较。Markdown 与结构化 JSON 导出只包含作答数据，不包括 AI 配置、密钥、原始 AI 对话、未确认草稿或浏览器凭据。

## 验收

纯函数回归验证逐题检查点、改判边界、未检验理由、旧版续答与指标独立性。真实 Chromium 验证切换、取消重答、刷新、修改中的不确定、可读导出、按需加载和窄屏阅读位置。必须同时通过内容结构检查和实际浏览器检查；单元通过不替代用户体验验收。
