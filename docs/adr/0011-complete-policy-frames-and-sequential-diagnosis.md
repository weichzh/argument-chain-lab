# 使用完整政策框架和顺序诊断替换组件式问卷

1.0 不再把“有条件支持”作为初始答案，也不再用组件平铺、包内取舍或多种评测模式补充原政策判断。每道题先呈现一个完整原方案；用户反对后，系统一次比较一个完整修改方案，并用两个框架的实际差异定位当前反对点。

这一决定保证用户接受、拒绝和说明理由的对象一致。固定题设只定义问题边界，修改方案必须对全部政策维度形成完整赋值，条件接受只能从“拒绝原方案并接受修改方案”派生。

0.9 会话无法可靠恢复被接受的完整框架，因此只读归档，不自动提升为 1.0 结果。旧模型保留在 `public/bank/legacy/`，当前 manifest 只加载 v4 模型。
